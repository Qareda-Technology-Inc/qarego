# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

QareGO is a ride-hailing, delivery (food/grocery/pharmacy) and parcel platform for Ghana. It is a multi-app repo with **no root package.json**. Each directory installs and runs on its own:

| Dir | Stack | Dev port |
|-----|-------|----------|
| `server/` | Express + Socket.IO + Mongoose (ESM, plain JS) | 2026 (`PORT` in `.env`) |
| `admin/` | Next.js 16 / React 19 / Tailwind 4 (TS) | 3000 |
| `merchant/` | Next.js 16 (TS), kitchen/store portal | 3001 |
| `client/` | Expo SDK 54 (RN 0.81, New Architecture) + Expo Router 6 (TS). **One app for both customers and riders** | Metro |
| `website/` | Vite + React landing page | Vite default |

## Commands

```bash
# server
cd server && npm run dev          # nodemon app.js
node seedAdmin.js                 # create first admin user (once)
curl http://127.0.0.1:2026/health
npm test                          # node:test money tests (test/*.test.js)

# admin / merchant
npm run dev        # local API (NEXT_PUBLIC_APP_ENV=development)
npm run dev:cloud  # point at production API
npm run dev:clean  # wipe .next first
npm run lint       # eslint
npm run build

# client
npm start              # runs adb reverse for USB devices, then expo start
npm run start:sim      # simulator, localhost packager
npm run start:cloud    # use EXPO_PUBLIC_PRODUCTION_API_URL
npm run android:device # native build to USB Android (handles Java/Gradle via scripts/)
npm run ios            # iOS codegen, then expo run:ios
npm run ios:fix        # iOS codegen + pod install
npm run lint           # expo lint
npx jest --no-watchman path/to/file  # single test (`npm test` runs jest --watchAll)

# website
npm run dev | npm run build | npm run lint   # lint = oxlint
```

Money rules (fares, food fees, commission, the food cash split) are tested on both sides against one shared case file, `server/test/fixtures/money-cases.json` (`server/test/money.test.js`, `client/src/utils/__tests__/money.test.ts`). If you change a rule, update both copies and the fixture.

`client/postinstall` regenerates the iOS codegen artifacts (`scripts/ensure-ios-codegen.js`). Re-run `npm install` or `npm run ios:fix` if native builds break after dependency changes. `react-native-maps` is pinned to 1.29.x and excluded from `expo install --fix` (`expo.install.exclude` in package.json), because Expo's recommended 1.20 lacks the iOS Google Maps plugin used here. `client/ios` and `client/android` are git-ignored and generated by `expo prebuild`.

iOS native build notes:
- `pod install` needs a UTF-8 locale: `export LANG=en_US.UTF-8`.
- `npm run ios` does not re-run `pod install` when the Podfile changes; run `npm run ios:fix` first.
- `plugins/withFmtCxx17.js` builds the `fmt` pod as C++17 (Xcode 26 rejects fmt 11's consteval with C++20).
- react-native-maps 1.29 adds Google Maps on iOS through its own config plugin (`iosGoogleMapsApiKey` in `app.config.js`), not Expo's `ios.config.googleMapsApiKey`.

## Architecture

### Server (`server/`)
- `app.js` wires everything: CORS allowlist (localhost:3000/3001, `ADMIN_ORIGIN`, `MERCHANT_ORIGIN`, plus LAN `192.168.*` outside production), Socket.IO, routers, static `/uploads` and `/sounds`. On start it ensures the `Settings{key:'global'}` doc exists (commission 15%, debt limit -100), seeds default commerce store types, and starts `foodCourierBroadcastScheduler`.
- The `io` instance is available as `req.io` / `app.get('io')`. Controllers emit socket events directly.
- Layout: `routes/` → `controllers/` (large files, ~7.4k lines total) → `utils/` (most of the business logic: dispatch, fares, settlement, push, SMS, Hubtel) → `models/`.
- Errors: throw classes from `errors/` (`BadRequestError`, `UnauthenticatedError`, `NotFoundError`). `express-async-errors` plus `middleware/error-handler.js` turn them into responses. No try/catch is needed in controllers.
- Auth: JWT bearer (`ACCESS_TOKEN_SECRET`) → `req.user = {id, phone, role}`. Roles: `customer | rider | admin | merchant | cook`. `/admin` and `/customers` use `requireAdmin`. Merchant routes use `merchantContext.js`: a `cook` is locked to one restaurant, and a `merchant` picks a store with the `x-restaurant-id` header.
- `/webhooks` (Hubtel MoMo) is unauthenticated and checked by `hubtelWebhookAuth.js`.

### Domain model
- `Ride` is the unit of rider work. `serviceType` is `RIDE | DELIVERY | FOOD`. Commerce vertical (`FOOD | GROCERY | PHARMACY`) and payment (`CASH | MOBILE_MONEY`) are stored on the ride. Status flow: `SEARCHING_FOR_RIDER → START → ARRIVED → IN_PROGRESS → COMPLETED`.
- A `FoodOrder` (used by every commerce vertical) creates a linked courier `Ride` (`FoodOrder.ride`) through `utils/foodOrderFlow.js`. Offers go to eligible riders via `rideOfferBroadcast.js` / `offerRanking.js` / `riderServiceEligibility.js`. Settlement is in `tripSettlement.js` and `foodOrderSettlement.js`.
- Who sees which price: the customer sees the full total (food + service fee + delivery). The merchant sees the **food subtotal only**, and merchant revenue figures use the food subtotal. The rider sees the fare, gross and net after commission.

### Real-time (`server/controllers/sockets.js`)
Rooms: `onDuty`, `rider_<id>`, `ride_<id>`, `food_order_<id>`, `customer_<id>`, `restaurant_<id>`, `chat_<rideId>`. Riders send `goOnDuty` / `goOffDuty` / `updateLocation`. Clients subscribe with `subscribeRide`, `subscribeFoodOrder`, `subscribeRestaurant`, `subscribeToriderLocation`. In-ride chat uses `joinChat` / `sendChatMessage`.

### Mobile client (`client/src/`)
- Expo Router lives in `src/app/`. `role.tsx` picks a role, which leads to `customer/*` or `rider/*`. Commerce screens are in the `customer/(commerce)/` group.
- `service/`: `apiClient.ts` + `apiInterceptors.tsx` (axios, token refresh), `WSProvider.tsx` (socket), and one file per domain (`rideService`, `foodService`, `commerceService`, …).
- State: zustand stores in `store/`, persisted with MMKV (`storage.tsx`).
- API target comes from `service/appEnvironment.ts`. `EXPO_PUBLIC_APP_ENV` sets dev or prod, and when unset it follows `__DEV__`. Dev auto-discovers the local API over USB/LAN.

### Admin & merchant web
- The browser calls `/api/*`. `next.config.ts` rewrites that to the backend chosen by `src/lib/appEnvironment.ts` (`API_PROXY_TARGET`, default `http://127.0.0.1:2026`, or `NEXT_PUBLIC_PRODUCTION_API_URL` in prod mode).
- Merchant sockets and uploads connect directly to `NEXT_PUBLIC_SOCKET_URL` / `NEXT_PUBLIC_API_BASE_URL`. Use the LAN IP for kitchen tablets. `NEXT_PUBLIC_*` values are fixed at build time, so redeploy after changing them on Vercel.

### Logic duplicated across apps
Some helpers exist in both `server/utils/*.js` and `client/src/utils/*.ts`, and some also in `admin/src/lib`: `offerRanking`, `earningsBreakdown`, `commerceOrderCopy`, `commerceVerticalTags`, `menuModifiers`, `mediaLimits`, `prescription`, `reviewLogin`, `parcelMode`, `currency`. They are not shared packages. When you change rules in one, check the copies.

## Deployment & config
API on Render (`https://qarego.onrender.com`), admin and merchant on Vercel, mobile via EAS (`client/eas.json`; Firebase files uploaded with `npm run eas:firebase-env`). Each app has a `.env.example`. More setup docs: `FIREBASE_PUSH_SETUP.md`, `server/HUBTEL_SETUP.md`, `server/ARKASEL_SETUP.md`.
